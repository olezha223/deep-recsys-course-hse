**MixFormer (2026)** — ещё одна сильная статья от ByteDance (arXiv:2602.14110), опубликованная примерно в то же время, что и TokenMixer-Large.

### Что они предложили

**Главная идея:** Решить проблему **co-scaling** (совместного масштабирования) sequence modeling (длинные пользовательские последовательности) и dense feature interaction (высокопорядковые взаимодействия статических фич).

До этого модели обычно делали **отдельно**:
- Sequence-модуль (LONGER, STCA и т.д.)
- Dense-модуль (RankMixer, Wukong и т.д.)
- Потом их либо стакают, либо конкатенируют.

Это приводит к конкуренции за параметры и вычисления, а также слабому взаимодействию между sequence и dense частями.

**MixFormer** — **полностью unified Transformer-style архитектура**, где sequence modeling и feature interaction происходят в **одном общем backbone** с **shared parameterization**.

**Ключевые компоненты MixFormer Block:**

1. **Query Mixer** (замена Self-Attention)
   - HeadMixing (перемешивание голов) + per-head SwiGLU FFN.
   - Лёгкий и эффективный способ обмена информацией между разнородными фичами.

2. **Cross Attention**
   - Non-sequential heads (из Query Mixer) выступают как queries.
   - Attend к последовательности поведения пользователя.
   - Per-layer SwiGLU FFN для проекции последовательности.

3. **Output Fusion**
   - Per-head SwiGLU FFN для глубокого слияния sequence + dense сигналов.

**User-Item Decoupling (UI-MixFormer)**
   - Разделение user-side и item-side голов + маска.
   - Позволяет использовать Request-Level Batching (RLB) — переиспользовать user-side вычисления для всех кандидатов в одном запросе.
   - Даёт ~36% экономию FLOPs при почти нулевой потере качества.

### Насколько это SOTA в 2026 году

**Очень конкурентоспособно**, особенно как **компромисс/альтернатива** между TokenMixer-Large и OneTrans.

- **OneTrans** — сильный акцент на unified Transformer + causal attention + pyramid + KV-cache.
- **TokenMixer-Large** — экстремальное масштабирование (до 7–15B) через Token Mixing + Sparse MoE + hardware optimizations.
- **MixFormer** — лучший **co-scaling** dense + sequence, отличная эффективность + простота unified backbone.

В таблицах сравнения MixFormer-medium обходит и STCA+RankMixer (stacked), и OneTrans, и другие SOTA при лучшем соотношении качество/FLOPs.

Online результаты тоже сильные (хотя чуть скромнее, чем у OneTrans в GMV).

В 2026 это один из топовых unified архитектурных подходов в промышленных рекомендациях ByteDance.

### Влияние на индустрию

**Прямое влияние (ByteDance):**
- Задеплоен в **Douyin** и **Douyin Lite** (feed recommendation).
- Значительный рост engagement-метрик:
  - Active Days, Duration, Like, Finish, Comment.
  - Особенно сильный эффект на low-active и middle-active пользователях.
- User-Item Decoupling даёт ощутимую экономию latency и FLOPs в продакшене.

**Широкое влияние:**
- Хорошо демонстрирует важность **unified parameterization** для co-scaling.
- Популяризирует HeadMixing + per-head FFN как эффективную альтернативу full self-attention в RecSys.
- User-Item Decoupling + RLB — полезный инженерный паттерн для всех, кто хочет масштабировать unified модели.

### Схема модели (MixFormer)

```
Raw Features
   ├── Sequential (User Behavior History, length T)
   │    └── Actions: item_id + type + timestamp + side info
   └── Non-Sequential (User + Item + Context)
        ↓

Feature Embedding + Splitting → N heads
        ↓

L × MixFormer Blocks
   ┌─────────────────────────────────────┐
   │ 1. Query Mixer                      │
   │    ├── HeadMixing (cross-head)      │
   │    └── Per-head SwiGLU FFN          │
   │                                     │
   │ 2. Cross Attention                  │
   │    ├── Query: from Query Mixer      │
   │    ├── Key/Value: from Sequence     │
   │    └── Per-layer SwiGLU FFN on seq  │
   │                                     │
   │ 3. Output Fusion                    │
   │    └── Per-head SwiGLU FFN          │
   └─────────────────────────────────────┘
        ↓ (residual connections everywhere)

Final Representations → Task Heads (CTR, etc.)
```

**UI-MixFormer вариант (с decoupling):**

```
Non-seq Features
   ├── User-side heads          (shared across candidates)
   └── Item-side heads          (per-candidate)
        ↓
   Query Mixer with User-Item Mask
        ↓
   Cross Attention (user heads attend to sequence)
        ↓
   Output Fusion
```
