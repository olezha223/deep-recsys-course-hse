**Cross Decoupling Network (CDN, 2023, KDD)** — статья от Google Research.

### Что они предложили

**Проблема:** В промышленных рекомендательных системах крайне выраженный **long-tail** по item’ам: несколько head-items получают почти все взаимодействия, а тысячи/миллионы tail-items — почти ничего. Обычные модели сильно bias’ятся в сторону head и плохо работают на tail.

Авторы провели анализ и показали, что bias возникает из **двух источников**:
1. Разница в распределении items (item prior p(i)).
2. Разница в условной вероятности предпочтения пользователя при данном item’е (p(u|i)).

Большинство предыдущих методов (reweighting, resampling, two-stage decoupling) решают только первую проблему и часто вызывают **forgetting** (забывание head при фокусе на tail) + деградацию overall performance.

**Решение — Cross Decoupling Network (CDN):**

- **Item side (Memorization vs Generalization Decoupling)**:  
  Разделяют features на memorization (ID, collaborative) и generalization (content, категории, tags).  
  Используют **Mixture-of-Experts**:
  - Memorization-focused experts
  - Generalization-focused experts
  - Frequency-based gating (head → больше memorization, tail → больше generalization).

- **User side (Sample Decoupling)**:  
  **Bilateral Branch Network**:
  - Main branch — обучается на оригинальном long-tail распределении (хорошие общие представления).
  - Regularizer branch — обучается на re-balanced данных (больше tail).
  - Shared tower для масштаба.

- **Cross Aggregation (γ-adapter)**:  
  Мягко объединяет вектора из main/regularizer и постепенно сдвигает внимание модели к tail во время обучения (γ контролирует скорость сдвига).

В inference используется только main branch → **никакого overhead’а на serving**.

### Насколько это SOTA в 2026 году

- **На момент публикации (2023)** — один из сильнейших академических результатов по long-tail в рекомендациях.
- **В 2026** — уже не самый новый, но **очень практичный и production-proven** подход. 
  - Новые unified архитектуры (OneTrans, MixFormer, TokenMixer-Large) решают более общие проблемы масштабирования, но CDN остаётся сильным специализированным решением именно для **long-tail**.
  - Хорошо сочетается с современными backbone’ами.

Особенно ценен тем, что **не ломает** overall performance и легко внедряется.

### Влияние на индустрию

**Прямое влияние (Google):**
- Успешно задеплоен в крупной production-системе (Google app ads / install prediction).
- Значительные gains:
  - Overall: +0.27% AUCLoss offline, +1.43% online KPI.
  - Sparse/Tail slice: +0.66% offline, **+3.75%** online.

**Широкое влияние:**
- Показал, что **cross-decoupling** (item + user) эффективнее простого two-stage или re-balancing.
- Mixture-of-Experts + frequency gating + bilateral branches стали популярными паттернами для long-tail задач.
- Подчеркнул важность **γ-adapter**-подобных мягких механизмов вместо жёсткого two-stage обучения.

### Схема модели (CDN)

```
User Features                  Item Features
   ↓                               ↓
Main Branch                  Memorization Experts
(Original long-tail)          (ID-like features)
   ↓                               ↓
Regularizer Branch           Generalization Experts
(Re-balanced data)            (Content features)
   ↓                               ↓
   Shared Tower                  Frequency-based Gating
   ↓                               ↓
      ┌──────────────────────────────┐
      │         γ-Adapter            │
      │ (soft shift to tail during   │
      │  training, main only at inf) │
      └──────────────────────────────┘
                    ↓
               Prediction Head
             (CTR / Install / etc.)
```

**Упрощённая структура одного блока (Item side):**

```
Item Features
   ├── Memorization features (ID, etc.)
   │     → Memorization Experts
   └── Generalization features (categories, tags)
         → Generalization Experts
                ↓
          Frequency Gating
                ↓
         Final Item Embedding
```
