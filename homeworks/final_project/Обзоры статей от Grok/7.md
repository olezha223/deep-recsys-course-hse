**TokenMixer-Large** — это большая промышленная статья от ByteDance (2026 год, arXiv:2602.06563), посвящённая масштабированию ранжирующих моделей в рекомендательных системах.

### Что они предложили

Авторы взяли свою предыдущую архитектуру **TokenMixer** (из RankMixer 2025) и серьёзно её эволюционировали, устранив ключевые bottlenecks при масштабировании до десятков миллиардов параметров.

**Главные инновации TokenMixer-Large:**

1. **Mixing & Reverting** (основное архитектурное изменение)
   - Вместо одного этапа mixing ввели двухэтапный процесс: **Mixing** (смешивание токенов) + **Reverting** (восстановление размерности).
   - Это решает проблему семантического misalignment и позволяет делать стабильные residual connections в очень глубоких моделях.

2. **Inter-layer (Interval) Residuals + Auxiliary Loss**
   - Дополнительные residual-связи каждые 2–3 слоя.
   - Auxiliary loss от промежуточных слоёв помогает нижним слоям лучше обучаться в глубоких сетях.

3. **Sparse Per-token MoE** (новая версия MoE)
   - "First Enlarge, Then Sparse" стратегия.
   - Per-token SwiGLU эксперты + shared expert.
   - Gate Value Scaling + Down-matrix small initialization.
   - Полностью **Sparse Train + Sparse Infer** (в отличие от RankMixer).

4. **Pure Model Philosophy**
   - Убрали почти все мелкие фрагментированные операторы (DCNv2, LHUC и т.д.) — они становятся бесполезны при больших масштабах.
   - Значительно выросла **MFU** (Model FLOPs Utilization) — до 60% в рекламе.

5. **Engineering optimizations**
   - Высокопроизводительные кастомные MoE-операторы (MoEGroupedFFN, Permute/Unpermute).
   - **Token Parallel** (специфичная модель-параллельность для per-token архитектуры).
   - FP8 inference (1.7× ускорение).

**Масштабы, которых достигли:**
- Offline: до **15B** параметров (Ads), **7B** (E-commerce).
- Online: **7B** и **4B** параметров в продакшене.

### Насколько это SOTA в 2026 году

На момент публикации (начало 2026) — **один из самых сильных промышленных результатов** в ranking-моделях для рекомендаций.

- Значительно лучше предыдущих SOTA: Wukong, HiFormer, DHEN, RankMixer, Group Transformer, FAT и т.д.
- Показывает чёткие **scaling laws** (производительность растёт с параметрами/флопсами) даже после 1B параметров.
- Лучшая комбинация эффективности + hardware utilization среди известных промышленных архитектур на тот момент.
- Особенно сильна именно в **очень больших масштабах** (многие предыдущие работы "ломались" при глубине и размере).

В 2026 году это, скорее всего, один из новых промышленных стандартов для ByteDance и сильный ориентир для других больших компаний (Meta, Alibaba, Tencent и т.д.).

### Влияние на индустрию

**Прямое влияние (ByteDance/Douyin):**
- **E-commerce**: +1.66% orders, +2.98% GMV (per-capita preview payment).
- **Advertising**: +2.0% ADSS.
- **Live Streaming**: +1.4% revenue.
- Обслуживает сотни миллионов пользователей ежедневно.

**Широкое влияние:**
- Показал, что в рекомендациях можно успешно масштабировать до 7–15B параметров с хорошим ROI.
- Продвинул идею "Pure Model" — отказ от зоопарка мелких операторов в пользу однородной мощной архитектуры.
- Token Parallel и оптимизации MoE-операторов полезны для всех, кто строит большие per-token / MoE модели.
- Укрепил тренд на **scaling laws в рекомендациях**, аналогично LLM.

### Схема модели (упрощённая)

```
Raw Features (User, Item, Sequence: DIN/SIM/LONGER, Cross features)
        ↓
   Semantic Group-wise Tokenizer + Global Token ([CLS]-like)
        ↓
   X = [X_global, X_0, ..., X_{T-1}]   (T tokens × D dim)
        ↓
   ┌─────────────────────────────────────────────────────┐
   │               TokenMixer-Large Blocks (L layers)    │
   │                                                     │
   │  Norm → Mixing (Head-wise concat + pSwiGLU)         │
   │         ↓                                           │
   │      Reverting (restore original token dim)         │
   │         ↓                                           │
   │  Per-token SwiGLU / Sparse-Pertoken MoE             │
   │         ↓                                           │
   │  Residual + RMSNorm + Interval Residuals            │
   │  (every 2-3 layers) + Aux Loss                      │
   └─────────────────────────────────────────────────────┘
        ↓ (stack L blocks)
   Mean Pooling over tokens
        ↓
   Prediction heads (CTR / CVR / etc.)
```

**Внутри одного TokenMixer-Large Block** (упрощённо):

```
Input Tokens (T × D)
    ↓
Norm
    ↓
Mixing (split by heads → concat → pSwiGLU + residual)
    ↓
Reverting (split back → concat per token)
    ↓
pSwiGLU / Sparse Per-token MoE (with shared expert)
    ↓
Residual + RMSNorm
    ↓
Output Tokens (same shape T × D)
```

Архитектура очень "чистая" и hardware-friendly по сравнению с предыдущими гибридными моделями.
