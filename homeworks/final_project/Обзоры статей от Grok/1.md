**TIGER (Transformer Index for GEnerative Recommenders)** — это работа 2023 года (NeurIPS) от исследователей Google (включая Shashank Rajput, Nikhil Mehta и др.). Она предлагает принципиально новый подход к retrieval (поиску кандидатов) в рекомендательных системах.

### Что они предложили?

Традиционные рекомендательные системы работают по схеме **retrieve-and-rank**:
- Dual-encoder (две башни) создаёт эмбеддинги пользователя (query) и всех items.
- ANN (приближённый поиск ближайших соседей, например, FAISS) находит топ-кандидатов по косинусному сходству или inner product.
- Потом ранкер ранжирует их.

**TIGER** заменяет это на **generative retrieval** (генеративный поиск):
1. **Semantic ID** для каждого item: вместо случайного атомарного ID (типа "item_123456") item представляется как **кортеж (tuple) семантических токенов** (например, (7, 1, 4, 0)).
   - Берётся контент item (title, description, brand, category и т.д.).
   - Предобученный энкодер (Sentence-T5) → dense embedding.
   - **RQ-VAE** (Residual Quantized VAE) квантизует embedding в иерархический tuple кодвордов. Это даёт **иерархию**: первые токены — грубая категория, следующие — более细-grained. Похожие items имеют общие префиксы.

2. **Генеративная модель**: Transformer-based seq2seq (encoder-decoder, похож на T5) обучается **авторегрессивно предсказывать** Semantic ID следующего item по истории взаимодействий пользователя (последовательность Semantic ID'ов + user token).

Модель **не ищет** в векторном пространстве — она **генерирует** ID кандидата токен за токеном (с beam search на inference). Transformer-параметры сами по себе выступают "индексом".

**Преимущества**:
- Лучшая обобщаемость (cold-start: новые items легко рекомендуются, если их Semantic ID похож на существующие).
- Знание sharing между похожими items.
- Меньше памяти на embedding table (не N items, а cardinality кодбуков × уровней).
- Возможность tunable diversity через temperature sampling.
- Прямая генерация (без отдельного ANN-индекса).

На Amazon Beauty/Sports/Toys они значительно обогнали SOTA того времени (SASRec, S³-Rec, BERT4Rec, P5 и др.) по Recall@K и NDCG@K (до +29% в отдельных метриках).

### Насколько это SOTA в 2026 году?

**Не frontline SOTA**, но **влиятельный фундамент** (цитируется >680 раз).

- **Идея Semantic ID + Generative Retrieval** стала популярной и эволюционировала: OneRec, LC-Rec, QARM, LLaDA-Rec, PinRec, PLUM и др. (2024–2026). Многие используют вариации RQ-VAE / RQ-KMeans / Product Quantization для токенизации items.
- Генеративные рекомендатели (особенно на базе LLM) — одно из горячих направлений. TIGER показал, что можно отказаться от классического двухбашенного ANN в пользу autoregressive генерации.
- В production (особенно крупные платформы) всё ещё доминируют гибриды: двухбашенные retrieval + reranker + generative компоненты. Чистый TIGER-подобный подход может быть дороже на inference (beam search), поэтому его улучшают (MoE, distillation, hybrid с ANN и т.д.).
- В 2025–2026 продолжают выходить работы, ссылающиеся на TIGER как на ключевую веху в "Generative Recommenders".

### Влияние на индустрию

- **Парадигмальный сдвиг**: Популяризировал **Semantic IDs** (иерархическую токенизацию items) вместо atomic/random IDs. Это помогает с cold-start, масштабом и generalization.
- Вдохновил множество follow-up работ в Google, Spotify, Kuaishou, ByteDance и независимых исследованиях.
- Есть open-source реализации и обсуждения в сообществе.
- Способствовал переходу части RecSys к "LLM-style" мышлению: items как токены, последовательности как текст, генерация вместо matching.

### Схема модели (TIGER)

Вот текстовое представление основной схемы (основана на Figure 1 и 2 из статьи):

```
User Interaction History
       ↓
[User Token] + [SemID1: c0,c1,c2,c3] + [SemID2: ...] + ... 
       ↓
   Transformer Encoder-Decoder (seq2seq, ~13M параметров)
       ↓ (autoregressive generation, beam search)
Predicted Semantic ID next item: (c0, c1, c2, c3)
       ↓ (lookup table)
     Recommended Item(s)
```

**Подробная двухчастная схема**:

1. **Semantic ID Generation (offline)**:
   - Item Content (title + brand + category + ...) → Sentence-T5 Encoder → Dense Embedding
   - RQ-VAE (Residual Quantization, 3–4 levels, codebook size 256) → Tuple (e.g., (7, 1, 4, 0))
   - Lookup tables: Item ↔ Semantic ID (для разрешения коллизий добавляют уникальный суффикс).

2. **Generative Retrieval (training & inference)**:
   - Input sequence → Transformer → Output: следующая последовательность токенов Semantic ID.
   - Во время inference: beam search → топ-K валидных Semantic ID → items.

Это позволяет модели "понимать" семантику items и генерировать релевантные даже для холодных items.
