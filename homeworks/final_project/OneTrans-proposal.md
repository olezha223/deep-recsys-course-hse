# Research Proposal

## Датасеты 

1) [Yambda-5B](https://arxiv.org/html/2505.22238v1). 

YaMBDa - это large-scale-датасет, построенный на логах Яндекс Музыки - крупнейшего стримингового сервиса в России.
Yambda-5B содержит 4.79 миллиарда взаимодействий между 1 миллионом юзеров над 9.39 миллионами треков.

На этом датасете мы будем стараться предсказать лайк и полное прослушивание. 

2) [VK-LSVD](https://dl.acm.org/doi/abs/10.1145/3774904.3792933).

Это тоже large-scale датасет, но от компании VK на домене рекомендации коротких видео. 
VK-LSVD состоит из более 40 миллиардов взаимодействий от 10 миллионов пользователей и почти 20 миллионов видео за шесть месяцев.

На этом датасете мы будем стараться предсказать лайк и репост другу.

## Протокол оценки качества

1) Предобработка и кодирование (для всех моделей, кроме ALS/TopPop)

Для непрерывных признаков используем Piecewise Linear Encoder  
- Для Concat-моделей: конкатенируем все
- Для HiFormer/OneTrans: либо оставляем как несколько отдельных токенов, либо группируем в 3-4 токена


Для категориальных признаков используем Multihash Transform.
   - Для Concat-моделей: добавляем в общий вектор
   - Для HiFormer/OneTrans: отдельный токен

Мультивалентные признаки кодируем через Multihash Transform + усреднение через embedding bag.
   - Для Concat-моделей: добавляем в общий вектор
   - Для HiFormer/OneTrans: отдельные токены


2) Temporal split

Так как timestamp в разных датасетах разные, мы будем разделять данные на train/val/test в пропорции 8:1:1. 

3) Метрики качества 

- Pairwise accuracy 
- AUC, UAUC
- Recall@100
- NDCG@100

4) Метрики эффективности (для всех моделей, кроме ALS/TopPop)

- Inference latency
- Peak GPU memory
- FLOPs 

5) Оптимизации, которые вводим в OneTrans

- [FlashAttention-2](https://arxiv.org/abs/2307.08691) (оригинальный OneTrans)
- Cross Request KV Cache (оригинальный OneTrans)
- [Speculative Decoding](https://arxiv.org/abs/2211.17192)
- [Hierarchical User Memory](https://arxiv.org/abs/2404.07143)
- [Candidate-wise Early Exit](https://arxiv.org/abs/2404.16710)
- [Adaptive Token Pruning](https://arxiv.org/abs/2106.02034)

## Бейзлайны

- TopPop - ранжирование по популярности
- iALS - классическая матричная факторизация
- [RankMixer](https://arxiv.org/abs/2507.15551) - ранжирующая модель с token mixing и MoE
- Transformer - это классический Transformer с одним токеном для вектора признаков
- [Hiformer](https://arxiv.org/abs/2311.05884) - модель с гетерогенными группами признаков и вниманием

### Модели и их входные форматы

| Модель | Формат входа | Как получен                                       |
|--------|--------------|---------------------------------------------------|
| TopPop, iALS | Индексы item_id | Без энкодинга                                     |
| RankMixer | Один вектор | Конкатенация                         |
| Transformer | Один вектор | Конкатенация                                      |
| HiFormer | Список токенов | Каждый признак/группа - отдельный токен           |
| OneTrans | S-токены + NS-токены | Специальный токенизатор (с историей пользователя) |

## Research Questions


### RQ-1: Какие оптимизации из LLM наиболее эффективны для модели OneTrans в рекомендательных системах?

Мы систематически сравним следующие оптимизации (по отдельности и в комбинации)

Гипотеза: Оптимизации, снижающие latency и memory (KV‑caching, FlashAttention, pruning) дадут наибольший прирост эффективности без потери качества. MoHE и иерархическая память улучшат качество на длинных последовательностях.

### RQ-2: Действительно ли OneTrans более эффективная архитектура, чем ее предшественники?

Сравнение будет проводиться при фиксированном бюджете FLOPs, а также при фиксированной inference latency (чтобы учесть разную вычислительную сложность). Метрики: pairwise accuracy, AUC, latency, memory.

Гипотеза: Unified архитектура OneTrans с mixed parameterization обеспечит лучшее качество при тех же ресурсных затратах за счёт совместного моделирования последовательностей и не-последовательных признаков.

### RQ-3: Насколько хорошо OneTrans обобщается между разными доменами (музыка vs короткие видео)?

Сравним разницу в относительном приросте OneTrans над бейзлайнами на Yambda‑5B (музыка) и VK‑LSVD (видео). Также проверим zero‑shot перенос: обучим на одном домене, протестируем на другом.

Гипотеза: OneTrans покажет схожий уровень улучшения в обоих доменах, что свидетельствует о его универсальности.
